# Boot and Registration Hazards

Review of PR #21 (`hazards/boot-registration`) verified against `integrate/first-run-safety-panel-rescue`
(PR #19) and `integrate/hazards-review`.

## Verdict table

| ID | Hazard claimed in PR #21 | Verdict | Evidence & action on `integrate/hazards-review` |
| --- | --- | --- | --- |
| H1 | Payload launches `LODS00001` or submits BGFT tasks with `user_id = 0` | **Already fixed by #19** (`P4N-28`, `REG-6`) | `foreground_user_id()` (`src/main.c`) requires `rc == 0 && user > 0xFF` at all 3 sites; `install_pkg()` (`src/install.c`) now also rejects `user <= 0xFF` as defense in depth. |
| H1b | `panel-app/main.c` `sceUserServiceGetInitialUser` only checks `rc < 0` and accepts `user <= 0xFF` (including 0) | **Real — fixed here** (`P4N-28`) | `panel-app/main.c` initializes `sys->user = -1` and rejects `rc != 0 || sys->user <= 0xFF` before opening Pad or VideoOut. Tested in `test/panel_lane_test.c` and enforced in `test/policy.sh`. |
| H2 | 120 s first-start timeout auto-saves defaults and mass-registers games | **Already fixed by #19** (`P4N-29`, `REG-8`) | Timeout completely removed from `main()`; enforced by `test/fw_sim.c` (`-DSTRICT_FIRST_RUN_SAFETY`). |
| H3a | Registration continues when `app.db-corrupt` or `DbCorruptionOccured` is present | **Already fixed by #19** (`P4N-30`, `REG-7`) | `dbguard` latches read-only corruption markers, klog lines, and DB error codes; halts all registration. |
| H3b | Empty-but-successful `app.db` read (`0` rows in `tbl_appinfo`) marks `db_ready() == 1` and treats every title as unregistered | **Real — fixed here** (`SYS-1`) | `db_snapshot_publish()` (`src/dbsnap.h`, used by `src/db.c`) rejects `new_count <= 0`; a live PS4 `app.db` always has system titles. Tested in `test/db_test.c` and `test/sysstate_test.c`. |
| H4a / H4b | `open_apps` returns `0` on `sysctl` failure; `mask_user_app` ignores running `LODS00001` | **Already fixed by #19** (`REG-11`) | `open_apps` returns `-1` on `sysctl`/alloc failure (now also on malformed `kinfo_proc` framing) and `mask_user_app` calls `open_apps(..., -1)`. |
| H5 | `install_all` force-unmounts `/user/app` after 120 s even while `g_install_busy == 1` | **Real — fixed here** (`REG-9`) | Added `dbguard_can_unmask(masked, install_busy)` (`src/dbguard.{h,c}`): `install_all` and `unmask_leftover` never unmount `/user/app` while `g_install_busy` is non-zero; they leave `g_masked = 1`, log the fault, and abort the batch. Tested in `test/dbguard_test.c`. |
| H6 | `readd_title` unconditionally calls `app_add` (and writes `badpatch`) even when `app_remove` failed | **Real — fixed here** (`REG-11`) | `readd_title` now runs `write_badpatch`, `wait_db_quiet`, and `app_add_internal(..., 0)` only when `app_remove` returns `0`. |
| H6b | `uninstall_title` detaches `AppUnInstall` thread after 60 s and returns `-2` while thread may still complete after `.src` rollback | **Real — open (hardware-dependent)** | Joining a wedged `sceAppInstUtilAppUnInstall` thread after rest mode would freeze the daemon permanently; safe cancellation requires console knowledge of `AppInstUtil` thread semantics. Kept documented as open. |
| H7 | `db_is_registered` used as proof of absence/presence in `app_remove`, `mask_user_app`, `install_all`, `register_finish` | **Real — fixed here** (`REG-11`) | `app_remove` now requires fresh `db_confirms_registered` or `db_confirms_unregistered` before unmounting or cleaning holds; `mask_user_app`, `install_all`, and `register_finish` require fresh confirmation. |
| H8 | `refresh_sandboxes` resets `g_nsandboxes = 0` before `getfsstat` succeeds | **Real — fixed here** (`REG-11`) | `refresh_sandboxes` allocates into a new buffer and swaps `g_sandboxes` / `g_nsandboxes` only after `getfsstat` succeeds (and bounds-checks `found < cap`). |
| H9 | `sceUserServiceInitialize` / `sceAppInstUtilInitialize` returns logged, not halted | **Already logged by #19; halting rejected** | Both return codes are already logged in `src/main.c` and `panel-app/main.c`. Halting on nonzero return would break normal PS4 boots where the host process already initialized the service (`0x80960003`). |
| H10 / H10b | `sceLncUtilLaunchApp` return ignored; `opened = 1` set once | **H10 fixed by #19; H10b intentional** | `lrc` is logged and notifies user on failure (`src/main.c`). One-shot `opened = 1` prevents a 1 s notification/launch spam loop (`P4N-28`). |
| H11 | No `sceUserServiceGetLoginUserIdList` / multi-user switch tracking | **Real — open (low severity, hardware-dependent)** | Foreground user is queried freshly on each action; multi-user switch semantics require console testing. |
| Atomic `config_save` (`P4N-32` -> `P4N-33`) | `config_save` cleared `setup_set(0)` before `write_file()` and ignored write errors | **Real — fixed here** (`P4N-33`, `SYS-2`) | Renumbered from `P4N-32` (collision with #20) to `P4N-33`. `config_save` uses atomic `write_file` (`durable_replace`), clears `setup_set(0)` only on success, and `app_config_set` rolls back `g_cfg`, language, and AutoRun on failure. |
| Source-scraping tests in #21 | `test/hazard_boot_test.py` and `test/hazard_api_baseline.txt` | **Rejected (brittle implementation tests)** | Regex scraping of C lines and hardcoded line-number baselines assert implementation layout instead of behavior (`AGENTS.md`). Replaced with behavioral C tests and clean `test/policy.sh` rules. |
